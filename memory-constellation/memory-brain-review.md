# Memory Brain 借鉴评估与统一知识库后续升级

用户目标：在同一个知识库中存知识、看星图、编辑与纠正、按问题联想调用。新增能力接入现有服务；不另装独立记忆库或建立第二个管理入口。

## 本轮升级状态

电脑端知识库、星图、按需工具和原自动召回已经共用一个召回服务。17 篇笔记、6 条摘要和81条原关系直接来自原存储；同页提供记忆管理，摘要也可打开原管理操作。没有另装 Python/SQLite 服务。

已经实现：关键词/本机语义排名融合、有界一跳关联、当前原文回读、来源/行号/修订、去重和字节预算、明确记住/更正/遗忘、可恢复版本，以及本地原文摘录与目录整理。真实 rc.1 AgentLoop 的模型请求捕获证明召回片段进入请求、纠正和关闭会更新上下文；现有云模型的知识库问答返回了有效原文编号。该证据不代表所有模型都必然主动选择工具。

本机约135万历史片段导致原全库扫描在6秒内未完成；现已利用同一代索引的来源缓存和读租约做知识库范围查询，实际相同问题约0.4秒返回语义候选。广泛历史查询仍受原超时限制，不宣称所有历史源都具有相同延迟。

## 吸收能力与实现边界

| 能力 | 接到当前统一知识库的位置 | 当前状态 |
| --- | --- | --- |
| 关键词 + 语义 + 关系候选融合 | Knowledge.memory / Knowledge.search，所有主入口共用 | 已实现；复用原本机 BGE 索引 |
| 有界关联扩展 | 真实笔记链接、共同标签，返回原因和路径 | 已实现一跳；不自动消歧或编造事实边 |
| 原文证据 | 当前笔记/摘要 ID、修订、原文行号和出处 | 已实现当前原文回读；没有新增完整聊天跨度核验引擎 |
| 少量记忆按需带入 | 原自动召回和按需工具，去重/条数/字节预算 | 已实现；原生请求捕获与云问答引用已验证 |
| 明确记住与纠正 | 当前真人逐字引文、原笔记/摘要版本机制 | 已实现；错误修订拒绝覆盖，笔记遗忘可从回收站恢复 |
| 后台整理 | 可重建的原文摘录与目录索引 | 已实现本地整理与独立的对话自动提炼；保留逐字依据，未证实结论作为待核实 |

统一流程为：资料进入现有知识库 → 可重建的关键词/语义索引与关系索引 → 问题触发查找 → 有界关联扩展 → 回读原文、去重及预算 → DSH 当前回答；同一批节点与关系在知识库图谱页显示。

“大脑”表示应用的外部存储和召回机制，不代表模型权重改变。该仓库 3D 脑体的落点和装饰纤维本身不等于语义关系。统一召回、关联依据和原文证据由本地适配实现。仓库独立 Python/SQLite 服务不直接作为第二套生产记忆安装。若后续复用具体代码，保留对应来源与许可证；本次仅借鉴设计并评估。

## 验收边界

1. 自然问题提到一个项目时，找出直接相关笔记，再补有明确边的关联资料；每项能说明为什么召回。
2. 原文改动、回收/恢复后无需手动同步星图，下一次查找以当前内容为准。
3. 超过预算时保留来源完整的少量片段，报告省略；索引失败能退回关键词，不能显示虚构结果。
4. 项目范围、记忆关闭、遗忘和来源失效检查贯穿所有检索通道。
5. 真正发起一条独立测试问答，观察最终模型请求与回答引用；不能用工具注册或模拟单测代替。

## 对话自动学习补充（2026-11-08）

用户进一步要求无需每次说“记住”也能积累知识。知识库0.4.0接入真实session/event的completed turn/end事件，普通本机对话完成后自动提炼，使用当前对话已有模型与账号。知识和候选都写入原notes状态，作业状态也在原工作台文件中，不新增第二个知识库。

模型只选择有长期价值的片段；程序核对逐字引文、活动消息身份、项目、原修订以及遗忘排除。用户陈述和工具观测保存原引文；模型提要保留为派生说明。助手未验证的建议及冲突条目不参与回答，直到用户核实。既有人工笔记不会被自动覆盖；明确纠正已有自动条目时保留历史版本。已召回的记忆工具输出排除在学习材料之外，避免把旧记忆反复复制成新知识。

支持暂停、每日额度、同页来源与最近结果、失败重试。仅处理开启后的新完成轮次，不批量扫描旧聊天。它提升外部知识的积累与调用，不训练模型权重或自动批准通用工作方法。验收记录在本任务 learning/ 目录。
