# 记忆星图 · DSH 统一知识库

基于 [yuyun-git/dsh-meow-constellation](https://github.com/yuyun-git/dsh-meow-constellation) 的 MIT 星图渲染；固定上游版本和原文件在 `upstream-source.json`、`upstream/`。当前适配版 `0.2.0-dsh-kb.1`，知识库工作台 `0.4.0`。

所有入口使用 `dshKnowledgeWorkbench.memory`：知识库搜索、图谱搜索、AI 问答、对话自动召回和按需工具共用同一服务。直接读写现有笔记/摘要各自的原文件，不安装第二个记忆数据库。

- **入口**：知识库 → 知识 → 笔记 / 搜索 / 记忆 / 图谱 / 回收站。图谱节点可打开原笔记或摘要编辑窗口，原笔记版本、导出和恢复功能保留。
- **联想**：当前原文关键词 + 原本机 BGE 语义索引的倒数排名融合；从前五个命中沿明确笔记链接或共同标签扩展一跳，每个最多六个邻居，显示关联依据。语义相似度不被保存为事实关系。
- **规模**：窄范围语义查询复用当前索引的校验缓存和读租约，只读取知识库对应来源；不扫描全部聊天，也不新建副本。允许的跨会话历史继续经过既有来源/项目设置，超时保留知识库结果并显示提示。
- **证据**：知识库索引命中后回读当前原文，返回 ID、修订、行号和来源；去重并限制条数和字节预算。删除、项目范围和暂停在异步检索后再次核验。历史材料只是参考。
- **管理**：`memory_constellation_manage` 接收明确的记住、更正、遗忘；绑定当前本机主会话的真人消息，保存正文必须出自逐字引文。笔记使用原版本/回收站；摘要保留历史和排除项，版本冲突或容量不足拒绝覆盖。
- **按需**：`memory_constellation_search` 和 `memory_constellation_read`，以及兼容的 `kb_memory_search` 使用同一入口。原自动召回钩子改用统一检索，没有新增另一条全量记忆注入流程，保留关闭、项目范围和共享来源设置。
- **自动学习**：普通本机主对话成功结束后，后台使用该轮实际模型挑选长期知识，每轮最多一个请求/三条候选、每日默认最多60次。新知识写入原笔记库，原文逐字跨度和会话记录可追溯；原有知识不会因提炼直接被覆盖。用户事实和工具观测以逐字依据参与召回；助手建议或冲突保存为待核实并暂不参与召回。明确纠正可更新自动条目并保留版本；重复/已遗忘的内容不重新入库。关闭、暂停、来源变更或模型失败会停止写入，记忆页提供状态与重试。不会回扫所有旧聊天，也不改变模型权重。
- **整理**：后台只生成可重建的原文摘录、目录位置和摘要索引 `knowledge/workbench/derived.json`；这一目录整理步骤不调用模型、不改原文。状态可见，失败可重试；对话提炼是上面的自动学习流程。
- **图形**：最多显示 500 节点；可视连线沿用原图谱的 120 篇/350 边上限。检索不受这一显示上限约束，关联检索覆盖当前允许的全部笔记。

HTTP 使用原 DSH 登录、真实本机连接及同源校验。错误明确显示，不用演示数据填充。外部知识源和全历史并不因此全部变成星图节点；旧资料中的冲突仍需用户核对。

## 构建、验证与部署

`node memory-constellation/build.mjs` 生成星图页面。测试需使用实际 DSH rc.1 SDK，将 `DSH_CONSTELLATION_TEST_ROOT` 和 `TMPDIR` 指向已登记任务的生成目录。覆盖统一搜索、原生 AgentLoop 请求、字节预算、项目范围、记忆修改/遗忘、容量/损坏恢复、索引读租约和安装回退。

`install.mjs` 安装星图包；统一升级还包含知识库的 `src/memory*.js`（含 `memory-learning.js`）、`service.js`、`notes.js`、页面和版本，以及 peer 的自动召回、兼容工具入口和窄范围索引检索。用 `deploy-unified.mjs` 核对已审阅安装基线的精确指纹后逐项替换。尤其不要把 canonical peer 的其他未发布改动覆盖到已安装文件。保留旧文件及插件链接，空闲检查后正常重启。
