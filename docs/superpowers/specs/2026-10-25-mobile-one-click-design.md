# DSH 手机点链接连接电脑：设计草案

日期：2026-10-25。状态：用户已确认方案并授权继续实现；公网部署尚未执行。

## 用户要看到的效果

首次在电脑点“连接手机”，复制链接或显示二维码；手机点击链接直接打开 DSH 手机版，确认连接后进入这台电脑。以后点手机版“电脑”即可再次进入，不再填写 IP、端口、中继地址或重复扫码。普通断网、换 Wi-Fi、手机回到前台、电脑 DSH 重启均保留配对，恢复网络和服务后重新连接。电脑关机或休眠期间明确显示离线。

## 当前核实的情况

- 规范桌面源码：`<desktop-source>`；规范手机源码：`<phone-source>`。两处均有已有修改，实施时只改本任务文件，不混入其它窗口的工作。
- 现有 peer 链接已经保存房间和设备密钥，使用 AES-256-GCM 加密业务数据。其链接还包含具体中继地址，无法跟随临时通道地址变化。
- 正式电脑当前保存的中继属于 `trycloudflare.com` 临时通道；已配对但未连通，状态另有“设备连接未启动”的错误。这条启动错误须单独复现定位，不能仅凭提示认定端口冲突。
- 历史实际部署记录也使用 Quick Tunnel；目前未找到已经部署的固定公网中继。不能把旧临时域名当成用户已有服务器。
- 手机版 Android Manifest 尚未注册 `dsh-phone://peer/connect` 外部入口，主 Activity 外部 Intent 也没有接入这个连接流程；当前主要依赖应用内粘贴。
- 手机顶部“电脑”目前优先读取 Pocket 保存的网址。Pocket 与旧 peer 是两条入口，不能只补 peer 链接却让按钮继续打开过期 Pocket 地址。
- ZCode 的参考实现使用固定 relay、设备身份、心跳和重连，不是依靠临时公网地址。仅借鉴流程，不使用 ZCode 的私有服务或凭据。

## 方案比较

1. 继续使用临时通道并自动启动：初次配置少，但地址变化后旧链接仍会失效，不满足长期使用的要求。
2. 固定域名的 Pocket Tunnel：可以减少地址变化，适合已有 Cloudflare 域名和隧道的使用者；仍要处理其登录会话以及手机版入口。
3. 固定加密中继与手机版设备配对：推荐。复用 peer 加密协议和同一电脑实例，将固定服务入口与设备配对持久化，增加真正的安卓点击入口与断线恢复。

目前未找到可复用服务器时，推荐准备 Cloudflare Workers + SQLite Durable Objects 的中继部署方案，使用固定 workers.dev 子域名，不要求先购买服务器或域名。正式部署需要用户自己的 Cloudflare 账号授权；只使用免费计划额度，不自动开通付费。固定地址不等于网络永远可达，须用用户实际 Wi-Fi 和移动网络验证。

## 实现边界

- 桌面端保存固定中继配置和启用意图，生成长期配对链接；正常启动时恢复连接。链接只有主动解除配对或重新生成时撤销，不把连接断开当成配对失效。
- 手机版增加严格限定的外部链接处理，覆盖冷启动和已打开应用；等待本机服务就绪后执行配对，首次显示电脑身份并确认，成功后打开电脑页面。链接和设备密钥不进入日志。
- 手机版保存连接类型，点“电脑”按已选择的设备路径重连；保留已有 Pocket、旧配对码、手机独立运行、API 同步和手机模型网关。
- 连接层增加有界的连接及握手等待、心跳失活检测、退避重连，以及网络恢复/返回前台时的及时恢复。清理旧连接和计时器，忽略过期连接回调，避免多个连接互相覆盖。
- 只自动重建连接，不自动重放聊天、工具、写文件或模型请求。重连后回到原电脑的同一会话读取结果。
- 远端中继只转发限定配对设备的密文，不公开电脑 3080、手机 8326 或用户工作区。部署须包含授权、连接数量/帧大小限制及撤销方式，不能变成任意人可用的公开转发服务。
- 原用户资料、账号、会话和其它窗口的未提交修改必须保留。正式安装、激活前核实当前任务，不中断在跑的任务；保留可核对的回退材料。

## 验收条件

1. 安卓外部点击链接在冷启动、热启动均可打开正确电脑；非法链接不会覆盖旧配对。
2. 手机 DSH 和电脑 DSH 分别重启后，原链接和保存的设备仍可使用；不必重新生成链接。
3. Wi-Fi 与移动网络切换、网络黑洞、服务器重启、电脑睡眠后唤醒能显示准确状态并恢复连接；旧连接不能抢回新状态。
4. 断线时已经提交的任务不自动重复执行；重连查看原会话。
5. 解除配对后旧链接/旧凭据被拒绝；现有加密、防重放和本机边界继续通过。
6. 保留手机本机模式、Pocket、已有扩展、API 同步和手机网关。源码测试、APK 构建、安装加载、实际跨网验收分别报告。

## 下一步需要用户确认

确认采用方案 3，以及在未找到既有固定服务时使用用户自己账号下的 Cloudflare 免费计划作为首个部署目标。账号登录或授权留到本地实现和可审查部署材料准备完毕后处理；不要求用户发送密码、私钥或 API Key。
