# 电脑版适配官方 0.2.1-alpha.4

本次将电脑版核心从 `0.2.1-alpha.1` 固定升级到 `0.2.1-alpha.4`（官方 tag `86a402200d95fecef4529d969836f1fe13c6cb0d`）。桌面运行时、锁文件、安装入口与 Mac 原生应用保持同一核心版本；Mac 应用壳更新为 0.1.1。官方发布说明：[alpha.4](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.4)、[alpha.3](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.3)、[alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.2)。

## 合并与兼容

逐文件校验官方 npm 包完整性，用 alpha.1 原产物、本地补丁与 alpha.4 原产物三方合并。保留输入框回车换行、独立发送按钮、模型搜索/来源筛选/收藏与最近使用、推理等级、ZCode 重置入口、原生会话删除、Noema 和已有本地插件。浏览器连接入口随上游改为 `client.browser.js`；模型选择器继续使用新版官方 Host 目录和选择协议。

子代理入口迁移为 `startActivation`，保留精确选模、并发/额度组限制、续发、冷恢复及总开关。已有 Profile 的完整预设可能仍含新版禁止的 `toolFilter`、`backgroundMode` 等字段；迁移器只处理本工程已验证的定时工具 deny 策略，使用单调工具 guard 保留对子代理的限制，普通主会话及用户创建的普通分支不受此限制。其他过滤器或旧 persona 在任何配置写入前明确拒绝，不能静默放宽权限。

CLI 安装器和 Mac 应用共用配置迁移器。旧人设中固定的 `Your working directory is {{cwd}}.` 目录句按官方指南删除，当前目录由新版必需的运行上下文提供；其余人设文字保留，未验证的自定义目录模板拒绝自动改写。迁移保留 YAML 中的 JS 标签、用户设置、账号引用和预设；备份原始配置并核对并发修改，重复执行不重复添加策略。分发包仅带编译产物时，以对应 JS 的已核对摘要验收，不要求使用者安装 TypeScript 源文件。缺失或被改写的必要运行文件仍会拒绝升级。

新版官方账号登录先预开 `about:blank`，收到 Host 授权地址后再跳转。Mac 壳保留这个隐藏占位窗口，在后续跳转时将地址交给系统浏览器并关闭占位窗口，修复一直“等待登录”却没有打开网页的问题。取消登录不启动浏览器；现有本地窗口和普通外链保留，未增加 Node、沙箱或协议访问权限。

## 验证范围

通过类型检查、安装/回退检查、真实 SDK 子代理派发和续发/冷恢复、普通输入框与附件上传组件、模型选择器多视口和错误恢复、Noema 原生引擎检查，以及账号轮换/网关 198 项回归。MCP、配对、卡片与配置同步 38 项检查通过。配置迁移检查覆盖无关设置与 JS 标签保留、精确回退、未知过滤器拒绝及并发修改后恢复；真实 SDK 验证子代理的模拟定时调用被拒绝而主会话可用，没有创建实际定时任务。

个人数据副本用于旧聊天恢复验收；原始账号密钥和聊天不进入源码或发行包。当前 Mac ARM64 实测不等于已在 Windows/Linux 实机验收，也没有以真实云模型扣费测试第三方登录和额度。

隔离副本恢复了两个真实旧会话，自动压缩实际触发 7 次，手动 `/compact` 完成一次。官方 `BrowserLogin` 组件在真实 Electron 44.7.2 下复现旧窗口策略阻止预开页，新策略完整交接一次授权地址并关闭占位窗口，取消流程不触发交接；该检查不发送真实登录或云推理请求。正式安装前后 4,235 个关键账号、聊天、技能和设置文件摘要一致，17 个现有插件组合保留。

## 正式窗口故障修复

正式 Mac 窗口复现 `Failed to load plugins / dsh-appearance-center: loading`。外观恢复原本等待资源加载后才返回插件初始化，现在同步完成注册并在后台恢复主题；资源慢或失败不会阻塞聊天启动，卸载会中止未完成的初始化。字体适配 alpha.4 的 `setFontSize(role, px)`，只修改正文大小，保留代码和终端各自字号。正式窗口热更新后已恢复，模型菜单实际显示 1,107 个模型；DeepSeek 账号设置显示已登录。

自定义中转路线没有内置 provider 目录时，原先空的模型输入声明回落到仅文本，使当前 apigo / glm-5.3-flash 在发送图片前被拒绝。现在仅对精确模型 ID 继承内置目录中一致的输入能力，同协议记录优先；显式模型声明和原生路线声明优先，未知或有歧义的型号保持来源默认值。模型列表响应中的显式输入类型也被保留。此适配不验证中转商的实际远端能力，真实端点拒绝仍按原错误返回。

新增外观启动/设置/安装与卸载恢复 9 项检查通过，四种视口下主题、字号、旧外观和读写失败恢复通过；中转模型能力 7 项检查通过。真实浏览器图片流程覆盖仅图片发送、字节编码、失败保留与重试，真实 SessionController 覆盖仅文本拒绝和图片准入并到达本地模拟模型。未发送用户图片到外部，也未调用付费推理。

正式完整重启及再次打开均已恢复输入框和模型入口；最新目录请求耗时约 0.62 秒，返回 1,111 个模型。ChatGPT 会员来源仍返回独立的连接错误，没有将该来源记为通过。182 份会话及所有原有账号引用保留；运行时凭据刷新、任务监督缓存及 SQLite WAL 检查点导致正常摘要变化，不能把这些变化误判为数据丢失。变动会话逐压缩帧解码后，备份中的 1,697 行均为当前 1,937 行的完整前缀。

## JetHub 转出 API 的图片链路补充修复

JetHub 现在把精确解析的输入能力与思考档位在同一次解析中导出，避免简略目录缺少图片字段时把可看图路线当成仅文本；明确的路线限制优先，失败保留原声明。网关在每次收图时取得当前附件服务，覆盖服务晚到和替换后的请求，Chat Completions 与 Responses 共用原有图片准入。

DSH 的“获取模型”可更新已有条目中未声明的输入能力，保留完整 provider/model ID、自定义名称、容量与明确的仅文本设置。取消选择或拉取失败保留原草稿。此前导入的 JetHub 来源，需在编辑来源中重新获取模型，应用所选并保存，补回丢失的图片能力。

真实浏览器两种视口、真实 SDK + 附件服务 + HTTP 网关的完整本地链路通过，Chat/Responses 图片都到达本地模型。旧实现下，四项网关回归与已有条目刷新检查会失败，恢复修复后通过。15 个网关测试文件共 386 项通过，相关 JetHub RPC 另 138 项通过；一项已有登录源码字符串断言在未修改的正式源码上也失败，本轮未改该登录逻辑或放宽断言。

## apigo2 本机调用失败与错误分类

本机 apigo2 调用 GLM-5.3-Flash 已实际复现 `42907：Credits不足，请充值或开启自动兑换`，与此前失败会话中的上游报错一致；它不是密钥失效。目录可读取145个模型，两个极短 OK 请求返回零用量响应，不能据此宣称普通推理通过；普通算术请求随即复现额度拒绝后停止扩测。没有修改密钥、计费设置或充值，用户需在 APIGOTO 后台核对可用 Credits、兑换与订阅。其他用户 Operit 与 DSH 的鉴权差异仍需那条实际报错，不以本机额度错误替代结论。

通用适配器按 APIGOTO 明确的 gateway_error/42906、42907 分类为 alpha.4 标准 QUOTA，默认停止无效重试；42901–42905/42908 等暂时限流保留原行为，未知错误不猜。保留 pi-ai 错误固定前缀中的上游 HTTP 状态，JetHub 兼容新版 QUOTA/AUTH/RATE_LIMIT 语义；Responses 的流式与非流式累积状态也保留 failure.status，避免真实403权限拒绝退化成401或502。

本地真实 PiAiAdapter + HTTP 上游 + HTTP JetHub 回放覆盖两套协议、两种流模式、额度/限流/401/403/未知错误和失败后恢复；不向外部发送业务内容。此前实现回放失败，修复后通过。官方依据：[错误重试](https://www.apigoto.com/apidoc/guide-errors.html)、[Credits与订阅](https://www.apigoto.com/apidoc/guide-billing.html)。

## 模型设置页长时间空白

实机测得 llm/listProviders、settings/describe 各约0.06秒，但 session/modelCatalog 因全来源联查耗时35.13秒。旧页面为了检查 DeepSeek 账号可用性而等待完整目录，导致所有中转卡片一起空白。现在本机配置与凭据状态完成后立即显示卡片，账号目录检查在后台完成；连续刷新共用未完成的账号请求，旧代际结果不覆盖新状态。初始读取显示明确加载提示。

真实 ModelsSection 与 ModelsSettingsStore 在1280、393视口下验证慢目录、无账号、初始读取提示、目录失败、并发刷新、凭据状态失败及提供商失败重试，初次本地卡片显示约0.18秒；旧实现因等待未完成目录而失败。完整正式窗口耗时另记录在本地交付回执；没有为此改变模型选择、密钥或账号设置。

正式 Mac 原生窗口重新打开后首次点击模型，约528毫秒即显示全部已配置中转卡片（含 apigo/apigo2），Host进程保持，后台原任务随后自然完成。已删除临时时序探针；最终程序与源码一致，安装包也含同一界面修复。
